# Wuwa Gacha Tool

一款专为《鸣潮》玩家打造的本地抽卡记录管理工具，帮助你追踪唤取历史、统计保底进度、复盘 UP 池表现。所有数据仅保存在本机，不会上传到任何服务器。

版本 v0.1.1 · 作者 Juliy

![banner](docs/screenshots/banner.png)

---

## 核心特性

- **三种数据导入方式**：游戏目录自动读取、抽卡链接直连、本地 JSON 导入
- **多账号管理**：同一台电脑上多个角色记录独立保存，一键切换
- **保底进度追踪**：每个卡池独立累计垫抽，距 80 抽保底一目了然
- **UP 池表现复盘**：自动统计不歪率、歪/不歪次数、平均抽数
- **多视角记录浏览**：列表、宫格、表格三种视图自由切换
- **手动补录五星**：按目标抽数插入五星，自动生成符合卡池规则的三星、四星记录
- **模拟记录编辑**：在表格视图中修改或删除手动补录数据，真实导入记录保持只读
- **按玩家导出 JSON**：在设置页按 UID 导出抽卡数据，格式与导入一致，可跨设备迁移或备份恢复
- **本地存储 + 删除前备份**：数据全程留在本机，清理操作前自动生成数据库备份
- **隐私安全**：不联网上报，不读取账号密码，仅解析本地日志与官方公开接口

## 界面导览

软件采用深色主题，顶部为自定义标题栏与导航，底部为状态栏，中间为三个主页面。

### 顶部导航栏

- 左侧显示软件标题与三个页签：**首页**、**记录**、**设置**，切换时有滑动指示动画
- 右侧依次为：
  - **玩家选择下拉框**（存在多个账号时显示），可快速切换当前查看的 UID
  - **刷新按钮**，重新读取本地设置、玩家列表与抽卡记录
  - **窗口控制按钮**（最小化 / 最大化 / 关闭）

整个标题栏可拖动移动窗口。

### 首页 · 抽卡概览

进入软件的第一站，集中展示当前账号的整体数据。

![home](docs/screenshots/home.png)

**数据导入（扫描抽卡）**

点击右上角「扫描抽卡」按钮，弹出扫描面板，提供三种方式：

| 方式      | 适用场景         | 操作说明                                                                                                   |
| --------- | ---------------- | ---------------------------------------------------------------------------------------------------------- |
| 游戏目录  | 最常用，自动读取 | 填入或选择鸣潮安装目录（需含`Client\Saved\Logs\Client.log`）。工具会自动解码日志、提取抽卡链接并拉取记录 |
| 抽卡链接  | 手动粘贴链接     | 直接粘贴从游戏内抽卡历史记录页面获取的完整链接                                                             |
| 导入 JSON | 迁移/备份恢复    | 选择本地 JSON 文件（格式需与游戏抽卡接口原始返回一致）                                                     |

> 前置条件：使用「游戏目录」或「抽卡链接」前，请先在游戏内打开一次抽卡历史记录页面，以便日志写入链接信息。

**提取抽卡链接**

在「游戏目录」模式下，填写目录后可点击「提取抽卡链接」按钮直接解码 `Client.log` 并展示完整的抽卡链接，支持一键复制。方便手动粘贴到「抽卡链接」模式使用，或分享给其他工具。

**概览仪表盘**

- **六项核心指标卡片**：累计唤取、五星数量、五星概率、平均五星抽数、每个 UP 角色平均抽数、每把 UP 武器平均抽数
- **记录时间范围**：展示已导入记录的起止日期，并提示官方链接仅保留近约 6 个月
- **当前垫抽**：按卡池列出当前垫抽进度条与「距保底 X 抽」，达到 66 抽会高亮提醒
- **UP 角色池表现**：展示不歪率、不歪次数与歪的次数
- **最近五星**：展示最近 6 条五星记录，含角色名、所属卡池、抽数与是否歪

### 记录 · 唤取记录

完整的抽卡记录浏览与检索页面。

- 卡池筛选列表：点击「全部卡池」或具体卡池进行筛选，每个卡池显示当前保底进度（如 `12/80`）

**主区域工具栏**

- **视图切换**：列表视图 / 宫格视图 / 表格视图

  - 宫格视图：卡片式布局，列数随窗口宽度自适应

- **结果计数**：实时显示筛选后的记录条数

![detail-insert.png](docs/screenshots/detail-insert.png)

**模拟记录管理**

- 手动插入生成的记录会标记为模拟数据，只有这些记录可以编辑或删除
- 表格视图可修改模拟记录的卡池、物品和时间，也可删除单条三星/四星记录
- 编辑模拟五星的时间时，同批次前置、后置补足记录会随五星一起移动
- 删除模拟五星会连同该批次尚存的全部补足记录一起删除
- 真实扫描或 JSON 导入的记录不提供编辑、删除入口，后端也会拒绝修改

**分页栏**

- 列表/表格视图下可调整每页条数（25 / 50 / 100）
- 宫格视图按列数自动计算每页数量
- 支持上一页 / 下一页翻页

### 设置 · 管理目录与数据

## 手动补录与卡池规则

手动补录用于补充缺失的五星记录。入口位于「记录」页面，填写的抽数表示该五星相对同一卡池上一个五星的实际抽数。

### 自动补足逻辑

- 插入在最新记录之后时，会先扣除同一卡池已经存在的垫抽。例如已有 30 抽、目标填写 70 抽，只新增 39 条补足记录和 1 条五星记录
- 插入在两个五星之间时，五星前只补齐目标抽数缺少的部分；五星后会补偿插入点前已有的垫抽，保证后一个五星原有抽数不变
- 五星前的补足记录默认放在目标时间前 1 秒；用于保护后一个五星抽数的记录放在目标时间后 1 秒，且不会越过下一条五星
- 不同 UID、不同卡池分别计算，彼此之间不会继承垫抽
- 插入计划会在数据库写入前重新计算；如果期间数据发生变化，本次插入会整体拒绝，不会留下半批记录

### 三星、四星生成

- 三星、四星物品从本地资源目录随机选择
- 四星基础出现概率为 6%，并保证每 10 抽至少出现一个四星或以上物品
- 生成时会同时检查插入点前后的既有记录，避免新旧数据拼接后出现连续 10 条三星
- 数据库层会再次校验补足数量、星级和四星保底，不能通过绕过界面的方式写入非法批次

### 五星与限定池校验

- 角色池只能选择五星角色，武器池只能选择五星武器
- 角色活动、新旅、联动和忆旅角色池遵循歪后下一次必为 UP 的规则
- 常驻角色池及武器池不应用连续歪校验
- 多条五星处于同一秒时，会使用与统计一致的稳定顺序判断相邻五星
- 抽数必须是 `1` 到 `80` 的整数；时间必须精确到秒

### 编辑后的统计

表格编辑以记录最终所在的位置为准。单独删除或移动三星、四星记录后，对应区间的五星抽数会自然变化；将五星移动到较远时间或其他卡池后，也会按新位置重新统计，而不是强制维持编辑前的抽数。

JSON 导出始终按记录时间从新到旧排列，不会因为模拟记录后来写入 SQLite 而改变顺序。再次导入真实记录时，真实记录只与真实记录去重，不会被同秒同物品的模拟记录错误覆盖。

## 使用流程建议

1. 首次使用：进入「设置」填好游戏目录并保存
2. 在游戏内打开一次抽卡历史记录页面
3. 回到「首页」点击「扫描抽卡」，选择游戏目录方式开始扫描
4. 扫描完成后即可在首页查看概览，在记录页浏览明细
5. 多账号用户可通过右上角玩家选择下拉框切换查看
6. 建议至少每半年同步一次，避免官方链接过期导致较早记录丢失

## 数据与隐私

- 所有抽卡记录保存在本地数据库，不会上传到任何服务器
- 工具仅读取游戏目录下的 `Client.log` 用于提取抽卡链接，不涉及账号密码
- 抽卡数据通过官方公开接口获取，与游戏内一致
- 删除操作前会自动备份数据库，可随时恢复

---

## 注意事项

- 官方抽卡链接仅保留近约 6 个月历史记录，两次同步间隔超过 6 个月，较早记录可能丢失且无法自动补回
- 使用游戏目录扫描前，务必先在游戏内打开抽卡历史记录页面，否则日志中无链接信息
- JSON 导入格式需与游戏抽卡接口的原始返回一致（含 `uid` 字段与各卡池编号键）
- 手动补录不会自动校正原始导入数据中已经存在的卡池规则问题；异常边界可能导致插入被拒绝
